Introduction

In agentic evaluations, a raw score alone is insufficient without the exact execution context. Minor variations in prompt templates, system instructions, tool permissions, or sandbox resources can cause massive performance swings.

To ensure every leaderboard score on AutomationBench is verifiable and replicable, Kaggle locks and publishes the complete Environment & Harness Configuration alongside every model run.

Pipeline overview

Evaluation structureTask Architecture

Evaluates models across 6 business domains with ~100 tasks each (~600 total). Each task executes as a multi-turn agent loop calling simulated enterprise tools.

 Runtime boundariesConcurrent Sandboxing

Runs inside isolated CPU notebooks (4 vCPU / 32 GB RAM) orchestrating 100 agent loops in parallel. High concurrency drives 10M–12M input tokens per minute.

 Evaluation integrityLeaderboard Grading

Zapier's automated grader validates the final application state of every workflow. Kaggle's Model Proxy logs per-call latency, token volume, and cost into a unified payload.

 Replicability standardPortability & Trust

Packages system instructions, harness versions, tool schemas, and sandbox hardware specs directly with the model score—eliminating environmental drift across runs.

Task Architecture

Domain execution harness

Each of the six domains runs as an isolated Kaggle Benchmark task that routes inference through the Kaggle Model Proxy.

import kaggle_benchmarks as kbench

@kbench.task(name="automationbench-sales")
def sales_domain(llm):
    # Executes 100 multi-turn agent workflows in parallel within the CPU sandbox
    results = automationbench.run(
        domain="sales",
        model=llm,
        concurrency=100,
    )
    return results.score  # Fraction of workflows passing end-state verification

Concurrent Sandboxing

Infrastructure evolution: notebook sessions vs. Harbor VMs

To maintain transparency as Kaggle's infrastructure evolves, we document how sandbox isolation shifts between launch benchmarks and newer container-orchestrated benchmarks.

Architectural dimensionLaunch setup (notebook sandbox)Next-gen setup (Harbor orchestration)
Isolation unit1 VM per domain (6 sessions total)1 VM per task (600 isolated VMs total)
Execution concurrency100 agent loops inside a single shared session1 agent loop per dedicated container VM
Model Proxy & token load10M–12M input tokens/min (identical)10M–12M input tokens/min (identical)
Replicability guaranteeLocked at the notebook environment levelLocked at the individual task container level
